# SpotFinder Firebase consumption and Firestore egress audit

**Date:** 2026-10-30. **Mode:** source inspection plus local synthetic serialization only. No production Firebase query, deployment, rules change, browser automation, or load test was performed. Counts below are *per invocation*, conditional on the named branch; they are not production request counts. Current source may differ from the October deployment. The reported 15.49 GiB and 14–15 CZK are user-provided billing observations, not an export available to this audit.

## 1. Executive summary

Five leading **source-backed risks**, ranked by possible Firestore transfer rather than measured production frequency:

1. A desktop map viewport reads up to **500 complete `spots` documents** per query and may issue a second 500-document query if padding fills the cap. Every `moveend` schedules this path, subject to a 120 ms debounce and caches ([Home.jsx:188–243](../src/pages/Home.jsx), [firebaseClient.js:571–600](../src/api/firebaseClient.js)). The `/new` mobile map cap is 300 ([MobileV2.jsx:348–385](../src/mobile-v2/MobileV2.jsx)). Full documents include descriptions and photo metadata, not a marker projection ([firebaseClient.js:493](../src/api/firebaseClient.js)). **High confidence in code; unknown production frequency.**
2. Nearby can re-read overlapping documents at expanding 25/100/400/1600/5000 km radii and paginate up to **1,500 unique candidates**. The cap applies to unique IDs, not cumulative document returns ([firebaseClient.js:615–660](../src/api/firebaseClient.js)). **High confidence in structure; data-dependent amplification.**
3. Opening the original Home map starts four public `admin_*` queries, each capped at 500, plus a fifth deleted-POI query capped at 1,000 ([Home.jsx:148–181](../src/pages/Home.jsx); [firebaseClient.js:1105–1237](../src/api/firebaseClient.js)). These are separate from spot reads. They may be small today; collection sizes are unknown. **High confidence in startup call count.**
4. Profile `Infinity` paths paginate **all** matching own spots, saves and likes; relation resolution adds batched spot queries and a permission-error fallback to one point read per ID ([MobileV2.jsx:551–553](../src/mobile-v2/MobileV2.jsx); [firebaseClient.js:663–685, 970–1009](../src/api/firebaseClient.js)). **High confidence in code; low confidence in typical size.**
5. Server-triggered recounts read every rating or vote for a spot; likes/saves use count aggregations and a spot read. They add operations after a user write ([functions/index.js:1012–1053, 1185–1205, 1483–1508](../functions/index.js)). These are unrelated to browser image downloads. **High confidence in code; unknown trigger frequency.**

The synthetic 1.9 KiB spot fixture measured **190,349 / 1,905,551 / 19,075,562 JSON bytes** for 100 / 1,000 / 10,000 spots. This is a local payload proxy, **not** Firestore wire size or billable egress. Firestore may add document names, field types, transport framing, and TLS overhead; compression and cache effects can move observed browser bytes in the other direction. No real production spot-size distribution was available.

## 2. Billing and measurement model

Let `Q` be server-executed queries, `D` documents returned (counting repeats), `B` serialized Firestore response bytes, `I` billable index-entry batches, and `R` distinct rules-dependent documents actually read. Approximate billable reads are `max(1,D)` **per query**, plus applicable `I` and `R`; point reads and transactions have their own charges. A local cache hit may avoid a server query; default `getDocs` attempts fresh server data when connected. Query calls, browser HTTP requests, returned documents, and billed reads are different quantities. One SDK operation can use multiple transport requests, and one browser action can issue several SDK operations. A zero-result query still has a one-read minimum. Two-range queries and `documentId()` plus another range may incur index-entry reads; exact counts require Query Explain or metrics. Count aggregation uses index entries, at one billed read per up to 1,000 entries with a minimum. [Firebase billing rules](https://firebase.google.com/docs/firestore/pricing), [default get behavior](https://firebase.google.com/docs/firestore/query-data/get-data).

There are **no `onSnapshot` listeners** in application code found by repository search. Thus a mounted map does not itself generate continual Firestore listener reads. If listeners are introduced later, additions/updates and reconnections can be billed; web offline persistence is disabled by default. [Firestore listener billing](https://firebase.google.com/docs/firestore/pricing), [offline behavior](https://firebase.google.com/docs/firestore/manage-data/enable-offline).

Security Rules dependent lookups occur in [firestore.rules:13–14, 101, 135, 143–145, 219–221](../firestore.rules). `canSubmit` can consult `submission_blocks/{uid}`; draft/rating gets can check their own document existence; rating and legacy flag creation consult a spot. Some repeated `get()` references to the same path may be cached during one evaluation, but actual billed dependent reads must be measured, not counted syntactically. Admin SDK calls bypass Rules. Denied requests do not prove zero Rules-read cost. [Rules pricing](https://firebase.google.com/docs/firestore/pricing), [Rules access-call limits](https://firebase.google.com/docs/firestore/security/rules-conditions).

`Storage` image bytes are separate from Firestore response bytes. A spot document carries image URLs/metadata, not the image file. Public image loading can use Firebase Storage URLs ([firebaseClient.js:378–423](../src/api/firebaseClient.js)); map tiles, PMTiles, Vercel snapshots, and geocoding are other network traffic, not Firestore billing. Firebase Auth, App Check token exchange/refresh, reCAPTCHA, and Functions calls must also be counted separately.

The current desktop two-query saturation branch or overlapping Nearby rings can multiply returns per interaction, but whether they did so in October is unknown. An idle current tab does not repeatedly query Firestore without other events. Limited registered-user activity does **not** constrain anonymous public map reads. The user-provided 14–15 CZK charge is broadly compatible with 15.49 GiB and a free outbound allowance, but billing SKU tiers, region, credits and conversion need the invoice/export; it cannot identify the requester. The billed SKU is **Cloud Firestore Internet Data Transfer Out Europe to Europe**. It is not evidence of Firebase Storage image downloads.
