# SpotFinder App Check readiness — no enforcement active

For the current staging isolation status, real-browser test budget, and service-specific readiness gates, see `docs/app-check-staging-runbook.md`. The older local test results below do not establish production enforcement readiness.

This change prepares client attestation and Vercel verification. **No Firebase product or Vercel route has App Check enforcement enabled by default.** No live Firebase request, deployment, billing change, Identity Platform upgrade, Storage activation, or reCAPTCHA API change was made. The combined local suite passed 20/20 tests with mocked App Check verification and a `demo-` Firestore emulator; after adding independent route switches, the focused App Check suite passed 6/6. Real registration and client behavior remain unverified.

## Local development and configuration

Development now fails before Firebase service initialization unless `VITE_FIREBASE_EMULATOR_ONLY=true`. Emulator-only mode uses `demo-spotfinder-local`, connecting Auth `9099`, Firestore `8080`, Functions `5001`, and Storage `9199` on loopback. It does not initialize production App Check. An absent emulator fails locally instead of reaching production. Nonproduction builds must explicitly target an isolated staging project or local emulators; local Vite preview rejects production-targeted build artifacts. No production debug token is accepted or bundled; a future isolated development Firebase app may use the [documented debug provider](https://firebase.google.com/docs/app-check/web/debug-provider) only with a separately approved registration and private token.

Production client build: `VITE_FIREBASE_APP_CHECK_SITE_KEY` is the **public score-based reCAPTCHA Enterprise key** registered to the exact Firebase web app. `VITE_FIREBASE_APP_CHECK_PROVIDER=enterprise` is accepted; `recaptcha-v3` is rejected. `isTokenAutoRefreshEnabled: true` is set. The SDK caches tokens and refreshes them around half the configured TTL; custom Vercel requests use `getToken(appCheck, false)`, so they do not force fresh attestation per request. Do not log tokens or put them in URLs.

Vercel server variables: existing `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`; add `FIREBASE_ALLOWED_APP_IDS` as a comma-separated exact allowlist and, later, the independent `VERCEL_APPCHECK_ENFORCE_CHECKOUT` and `VERCEL_APPCHECK_ENFORCE_SUBSCRIPTION_STATUS` switches. The report API requires App Check whenever its own pilot gate is enabled. No `VITE_` variable may contain service credentials. The Admin SDK verifies token signature, expiry, and project; `appCheckGuard.js` also checks the configured Admin project and exact decoded app ID. A missing allowlist/configuration fails closed when enforcement is on. Existing report pilot switches and Turnstile secrets remain separate.

## Manual Console setup and rollout

1. Confirm current Spark/billing status and the exact web app registration without changing the plan. Create or inspect a score-based reCAPTCHA Enterprise web key for production hostnames (`spotfinder.live` and any other actually served hostname). Do not put localhost on that key. Check [pricing and quotas](https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider) before key creation or API activation; do not enable paid services for this task.
2. In Firebase Console App Check, register that key to the exact SpotFinder web app. Keep Firestore, Storage, Functions, and Auth enforcement **off**. Build the client with the public site key and verify the app ID/project ID, Auth restoration, anonymous browsing, map data, drafts, photos, callables, and Vercel requests in an isolated environment.
3. Deploy the client initialization **alone**, after explicit approval, while enforcement stays off. Observe App Check verified, unverified, and outdated request metrics per product across normal usage, old cached bundles, browsers, tabs, and WebViews. A unit test is not a readiness gate. Require a full representative usage cycle and a known rollback owner.
4. Enable the report pilot only after its App Check path is verified; its App Check requirement is inseparable from the pilot gate. Enable the remaining Vercel route switches one at a time only after each browser path sends valid tokens and exact app IDs are registered. Enable Firebase product enforcement **one at a time**: first a low-volume callable, then remaining callables, then Storage if available, then Firestore last after public map and legacy clients are verified. Auth is deferred unless Identity Platform is already active and separately approved. Monitor 401s, successful reads, map availability, uploads, and login immediately after each step.
5. If 401s or broken flows occur, turn off only the just-enabled product's enforcement (or that route's `VERCEL_APPCHECK_ENFORCE_*` switch) first. Keep prior client build available and clear/redeploy bad build configuration after access is restored. Never weaken Firestore/Storage rules or remove Auth checks as a workaround.

App Check does not rate-limit a legitimate client. Firestore egress can still grow from repeated queries, full document payloads, or public SDK use. Turnstile is a separate risk-based action challenge; it never substitutes for App Check, Auth, rules, or the report hard cap. Shorter App Check TTLs increase reCAPTCHA assessments and potential charges; use the default one-hour TTL initially. Firebase Admin and Functions background operations also have their own billing/quota behavior, and Spark may stop service when quotas are exhausted rather than charge overages.

## Verification gaps

Local tests cover pure token configuration/refresh delegation and mocked Vercel verification. They do not prove production reCAPTCHA Enterprise registration, token delivery, Auth Identity Platform status, Storage availability on Spark, old browser bundles, WebView behavior, or Console metrics. No production App Check metrics or settings were read in this task. Browser automation is prohibited by repository instructions, so reload, multiple-tab, React remount, and recovery UX require later manual preview checks.
